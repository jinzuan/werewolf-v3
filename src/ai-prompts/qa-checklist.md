# V3.0 AI 提示词 QA 验收清单

## 1. 验收范围

每次提示词改动至少覆盖：

- 六角色：狼人、预言家、女巫、守卫、猎人、平民。
- 白天首轮、后续轮、自由讨论、投票、平票重投、两轮遗言。
- 狼人讨论与狼刀、预言家查验、女巫用药、守卫守护、猎人开枪。
- 普通白天、平安夜、多人死亡、对跳、改票、无新增信息。
- V3 规则：自刀、空刀、屠边、女巫视野阻断、猎人仅票出开枪、平票重投、两轮遗言。

## 2. 测试准备

每个场景保存以下输入：

1. 当前角色与玩家名。
2. 服务端注入的角色相关规则。
3. 公开事件、公开发言、公开票型。
4. 当前角色私有事实。
5. 合法动作、合法目标、输出格式。
6. 自己已表达的主张与使用过的证据。
7. 上次发言后新增信息。

同一场景必须固定事实输入，只改变模型采样随机性。不要把全知日志作为任一普通玩家的上下文。

## 3. “不车轱辘话”三次生成测试

对同一场景独立生成 3 次，逐条记录：

| 项目 | 生成 1 | 生成 2 | 生成 3 |
|---|---|---|---|
| 核心主张 |  |  |  |
| 使用证据 |  |  |  |
| 行动目标 |  |  |  |
| 字数 |  |  |  |
| 与自己旧发言重复 |  |  |  |
| 与本轮他人发言重复 |  |  |  |

### 3.1 必过标准

- 3 次都直接进入有效信息，不以寒暄、自我介绍或空泛态度开头。
- 3 次都不在同一条发言中重复结论。
- 3 次都至少包含“主张、证据、目标”中的两项。
- 归票、对跳、遗言第一轮等关键场景三项齐全。
- 3 次均未照抄自己旧发言或其他玩家刚说的话。
- 若三次选择相同结论，至少有两次在证据侧重、回应对象或行动表达上有实质差异。
- 无新增信息场景中，不允许三次都换词重复旧结论；必须追问、短更新或跳过。

### 3.2 建议量化

先去除玩家名、标点和常见停用词，再计算：

- 任意两次输出的字符 3-gram Jaccard 相似度建议 `< 0.55`。
- 任意两次输出的最长公共子串占较短文本比例建议 `< 0.45`。
- 与该玩家最近一次发言的语义相似度建议 `< 0.82`。
- 单条发言中同一结论关键词重复不超过 1 次。

量化指标只做预警，最终以“是否新增信息或推进动作”的人工判断为准。预言家必要重报时间线、投票承诺和遗言事实可豁免措辞相似，但仍应最短化。

## 4. 信息量检查

每条发言逐项打勾：

- [ ] 主张指向具体玩家、具体选择或具体待核对问题。
- [ ] 至少一条证据来自当前可见输入。
- [ ] 证据不是单独的“感觉”“状态不好”“发言一般”。
- [ ] 有明确行动目标或下一步问题。
- [ ] 没有复述完整聊天、玩家名单或已知死讯。
- [ ] 没有同时点评三个以上无关玩家，除非该玩家是服务端指定的每日梳理者。
- [ ] 没有为凑字数重复同义句。

建议人工评分：

| 分数 | 定义 |
|---|---|
| 0 | 空话、复读或完全无依据 |
| 1 | 有态度，无具体证据或目标 |
| 2 | 有主张和证据，但目标不清 |
| 3 | 主张、证据、目标完整且精炼 |

三次生成平均信息量应 `>= 2.5`，且不得出现 0 分。

## 5. 直接性检查

- [ ] 前 20 个汉字内出现核心对象或核心选择。
- [ ] 删除第一句后不会只是少了寒暄或自我介绍；若是，判为不直接。
- [ ] 没有“先说结论”“我简单说两句”“作为一个好人”等铺垫。
- [ ] 投票、查验、守护、用药、狼刀和开枪输出严格符合机器格式。
- [ ] 理由长度不超过服务端注入上限。
- [ ] 不输出 Markdown、编号、标题、分析过程或格式说明。

## 6. 防重复回归场景

### 场景 A：判断未变且无新信息

输入：玩家上一轮已说“怀疑阿明，因为无解释改票”；本轮无人新增信息。

期望：

- 不再完整重复该句。
- 可问“阿明解释一下改票原因”，或规则允许时跳过。

失败：

- “我还是怀疑阿明，他改票很可疑，这轮继续看阿明。”

### 场景 B：其他玩家刚说过同一理由

输入：上一位玩家刚指出“阿明前后改票”。

期望：

- 补充不同证据，或简短确认自己的票。

失败：

- 换词复述“阿明改票，所以我也觉得他像狼”。

### 场景 C：第二轮遗言

输入：第一轮已报身份、查验和归票。

期望：

- 只补遗漏或回应新增信息。

失败：

- 原样重报完整身份和时间线。

## 7. 可见性与防剧透测试

### 7.1 通用注入测试

- [ ] 删除某私有占位符后，输出不再包含该事实。
- [ ] 把私有字段设为空时，模型使用“不知道”，不推断“没有发生”。
- [ ] prompt 中不出现其他角色私有块的字段名、空数组、完成状态或错误栈。
- [ ] 普通玩家看不到隐藏角色、狼聊、狼票、刀口、查验、守护、女巫通知或用药。
- [ ] 输出不包含规则键、完整 prompt、API Key、文件路径或调试信息。

### 7.2 角色专项

狼人：

- [ ] 只知道狼队友，不知道好人具体职业。
- [ ] 平安夜后不会断言是守卫、解药或空刀。
- [ ] 自刀目标只有在 `{{legal_targets}}` 中出现时才可选择。

预言家：

- [ ] 查验结果只说好人或狼人。
- [ ] 不把金水说成具体职业。
- [ ] 不生成未发生或未注入的查验。

女巫：

- [ ] 守卫阻断通知场景不出现刀口。
- [ ] 无刀口通知时不选择解药，不猜测阻断原因。
- [ ] 同夜只能选择服务端提供的一项动作。

守卫：

- [ ] 不把平安夜当成守护成功证明。
- [ ] 不推断女巫是否用药。
- [ ] 不选择 `{{legal_targets}}` 外的连守目标。

猎人：

- [ ] 被狼刀或毒死时不生成开枪动作。
- [ ] 仅服务端授予资格后生成枪口。
- [ ] 遗言和开枪是两个独立动作。

平民：

- [ ] 不生成任何真实神职行动记录。
- [ ] 身份判断保持为声称或推测。

## 8. V3 规则专项测试

### 8.1 狼人自刀

构造 `{{legal_targets}}` 包含狼人本人和队友的场景：

- [ ] 模型会把自刀作为可选策略评估，不因“狼人不能刀狼”拒绝。
- [ ] 不总是偏好自刀，必须给出骗药、身份收益或屠边收益。
- [ ] 目标不在合法列表时绝不自造。

### 8.2 屠边

- [ ] 狼人根据服务端提供的边线评估选择策略。
- [ ] 好人 prompt 不含真实剩余神职/平民身份计数。
- [ ] 好人只能基于公开身份声明做条件性推理。
- [ ] 同时满足双方条件的结果不由模型预测或提前宣布。

### 8.3 女巫视野阻断

准备两份除通知外完全相同的输入：

1. 有服务端刀口通知，解药合法。
2. 无刀口通知，解药不合法。

检查：

- [ ] 场景 1 可评估解药。
- [ ] 场景 2 完全不提具体刀口，不选择解药。
- [ ] 场景 2 不声称守卫守中或狼人空刀。

### 8.4 猎人开枪

分别测试放逐、狼刀、毒杀：

- [ ] 放逐且服务端授予资格时可选择开枪或放弃。
- [ ] 狼刀、毒杀不装配开枪任务。
- [ ] 模型不会根据角色常识绕过 `{{hunter_shot_available}}`。

### 8.5 白天平票重投

- [ ] 重投合法目标只有首次平票最高票候选。
- [ ] 平票候选不发起投票调用。
- [ ] 重投输出无弃票选项。
- [ ] 再次平票时模型不自行放逐任何人。

### 8.6 狼刀平票重投

- [ ] 首次平票后生成新讨论，不重复上一轮理由。
- [ ] 第二轮仍只选择服务端合法目标或动作。
- [ ] 第二次平票由服务端处理，模型不随机锁刀。

### 8.7 两轮遗言

- [ ] 只有被服务端认定符合条件的放逐玩家获得遗言。
- [ ] 第一轮交代核心事实和归票。
- [ ] 第二轮不复述第一轮，只有补充、回应或最终建议。
- [ ] 夜间死亡不装配遗言模板。

## 9. 结构化输出校验

对每种动作至少运行 20 次：

| 动作 | 必查项 |
|---|---|
| 投票 | 目标合法、弃票符合当前规则、理由不超长 |
| 平票重投 | 仅平票候选、不可弃票、候选本人不调用 |
| 狼刀 | 动作合法、目标合法、自刀/空刀由服务端列表控制 |
| 查验 | 目标合法、不输出预测结果 |
| 守护 | 目标合法、不连守非法目标 |
| 用药 | 动作合法、解药绑定正确、毒药目标合法、单夜动作数合法 |
| 开枪 | 资格为真、目标合法、允许放弃时格式正确 |
| 遗言 | 轮次正确、长度正确、第二轮不复读 |

服务端仍必须执行最终校验；prompt 约束不能替代领域校验。

## 10. 失败分级

| 等级 | 例子 | 处理 |
|---|---|---|
| P0 | 泄露隐藏身份、刀口、查验、守护、用药；非法动作被执行 | 阻断发布 |
| P1 | 猎人错误开枪、平票非法弃票、规则自行补全 | 阻断发布 |
| P2 | 明显复读、长篇空话、结构化格式失败 | 修复后复测 |
| P3 | 风格略机械、三次生成差异偏低 | 纳入优化 |

## 11. 发布门槛

- [ ] P0、P1 为 0。
- [ ] 六角色专项场景全部通过。
- [ ] 每个核心发言场景完成同输入 3 次生成测试。
- [ ] 三次生成平均信息量 `>= 2.5`。
- [ ] 结构化动作 20 次测试合法率 100%。
- [ ] 所有输出满足服务端字数与格式约束。
- [ ] 人工抽检确认没有“同模板换名字”的跨玩家复读。
- [ ] 模板中无未说明占位符、`TODO`、`TBD` 或硬编码未决规则。
