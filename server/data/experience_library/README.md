# 狼人杀经验库（V3 服务端）

本目录包含 33 个 AI 行为参考资产。它们来自旧版经验库，已迁移到服务端并在 **2026-08-14** 完成结构化调优。原始知识库只读保留在每个文件的“原始迁移内容（逐字保留）”段落中；结构化段落位于文件顶部，作为当前优先参考。

## 当前规则优先级

经验不是规则。模型必须遵循以下优先级：

1. 服务端注入的 `rules_for_role`、`legal_actions`、`legal_targets` 和真实私有事实；
2. 当前角色可见的公开事件、发言、票型和上下文摘要；
3. 本目录文件顶部的结构化决策要点；
4. 文件底部的原始迁移内容，仅作来源与补充参考。

与当前 V3 规则相关的关键修正已经在结构化段落中明确：

- 狼人允许自刀、选择狼队友、空刀；狼刀平票由服务端随机杀一个；
- 胜负按屠边：神职全部出局或平民全部出局；
- 猎人当前为放逐出局触发开枪，被毒/被狼刀不得自动开枪，服务端允许时可以跳过；
- 平安夜不能自行推断守护、解药、空刀或其他原因；
- 女巫没有刀口通知时不得猜测刀口或选择解药；
- 预言家查验按服务端提供的阵营粒度表达；警徽流等旧板子字段不能自行补全；
- 一次 AI 调用只输出一个服务端允许的动作。

## 注入与使用方式

服务端通过 `experienceLibrary.getReference(role, stageRevision)` 按角色选择一份角色经验，并拼接一份通用经验。`stageRevision` 保证同一角色不会永远固定使用同一份文件。V3 prompt builder 通过 `{{experience}}` 注入该参考，并明确声明它不覆盖规则、事实和合法动作。

建议的使用顺序：

- **白天首轮**：`common_1` + 角色基线（如 `seer_1`、`villager_1`、`wolf_1`）。
- **白天后续/讨论**：按当前问题选择逻辑、带队、潜水、悍跳或对跳变体；只推进一个新问题。
- **投票/平票**：优先 `common_3`，再选角色的归票/控票文件；平票只使用服务端给出的候选。
- **夜间**：角色文件优先于通用文件；守卫看守护链，女巫看通知/药态，预言家看查验历史，狼人看狼聊/屠边/合法刀口。
- **遗言/开枪**：只陈述服务端真实提供的私有事实，并遵循当前输出契约。

## 权重建议

经验库当前不把权重写入运行时协议，建议由调用方按以下优先级理解：

- `P0`：硬规则、合法动作、服务端私有事实（不可被经验覆盖）；
- `P1`：当前阶段、当前角色和最新公开信息直接相关的结构化决策；
- `P2`：同角色的风格变体、长期策略和表达建议；
- `P3`：原始迁移内容中的泛化经验，仅在不与前述信息冲突时参考。

防复读时，优先使用“新信息 + 新证据 + 新行动”，不要把经验条目本身复述成发言。

## 来源、去重与完整性

- 33 个原有文件名全部保留，没有删除原始条目；
- 重复/合并关系写在每个文件的“去重/合并说明”与 `EXPERIENCE_REVIEW.md`；
- `manifest.json` 只登记 33 个经验资产，`README.md` 不计入资产清单；
- 每次修改经验文件后必须重新计算 SHA-256，并运行经验库完整性测试。
